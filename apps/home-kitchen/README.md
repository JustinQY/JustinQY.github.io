# 今天吃什么 · 我们的小厨房

供两个人使用的私人菜谱与点菜网页。当前是**本地测试版，尚未部署到 DigitalOcean**。

## 本地打开

需要 Node.js 24 或以上版本。当前 Mac 已安装适用版本。

```sh
cd /Users/qiaoyibo/qyb_blog/apps/home-kitchen
npm ci
npm start
```

打开 <http://localhost:4310>。默认只监听本机。

手机测试时，在同一 Wi-Fi 下运行：

```sh
HOST=0.0.0.0 npm start
```

电脑打开页面，首次设置好两个账号，再点击页面底部的「手机打开」获取局域网链接和二维码。手机用自己的账号登录。Mac 和服务需要保持运行；如果 macOS 提示本地网络访问，应按你期望的测试范围授权。

本地链接是 HTTP。只适合在可信的家庭网络中测试。微信可能对局域网链接提示或限制访问；这种情况可以先用 Safari/Chrome 验证。正式服务器上的 HTTPS、微信扫码、蜂窝网络访问，需在你确认本地版本后另行配置和实测。

## 首次设置与使用

1. 首次打开自行设置掌勺账号和点菜账号，密码至少 8 位。没有默认密码。
2. 可选择加入 4 道明确标记的示例菜谱；配图是本地绘制的示意插画。示例可编辑或删除。
3. 掌勺账号在「我的菜谱」添加菜品、照片、基础人份、食材用量和做法。照片在浏览器中压缩成最长边 1600px 的 JPEG 后上传。
4. 在「今天吃什么」发起一餐，选择可点的菜品。对方登录后选菜并提交口味备注。
5. 掌勺账号确认最终菜单与每道做几份。例如，2 人份的菜 × 2，食材用量翻倍。同一道菜被两个人点选不会自动翻倍。
6. 「采购清单」按食材名称和单位合并数量，可标记待购买、家里有、买好了。两个人都能更新。
7. 确认菜单时保留菜谱快照；后续修改或删除菜谱不会改变这餐的做法与清单。重新调整菜单会清空采购勾选状态，但保留点菜记录。

打开页面时，每 10 秒更新一次数据。正在编辑表单或对话框时暂停刷新，避免输入被打断。

## 数据与权限

- 数据库、照片、账号和会话保存在 `.data/kitchen.sqlite`，已加入忽略规则。
- 使用 Node 内置 SQLite；唯一的 npm 运行依赖是本地生成二维码的 `qrcode-generator`。
- 密码使用随机盐和 scrypt 哈希；会话使用随机令牌、HttpOnly / SameSite cookie；所有厨房数据与照片接口都要求登录。
- 掌勺账号可管理菜谱、发起和确认菜单、导出数据；点菜账号可选菜、查看做法和更新采购状态。
- 页面不加载外部字体、图片、分析代码或第三方二维码服务。
- 「导出厨房数据」是包含照片的内容导出，不含密码和会话。目前未实现导入功能；完整恢复或迁移请保存数据库文件。
- 完整备份时先正常停止服务，再复制整个 `.data/` 目录；不要只在运行中复制 SQLite 主文件，因为最新内容可能还在 WAL 中。
- 尚未提供找回密码或修改账号的界面，请记好首次设置的账号密码。

## 配置

通过启动环境变量配置（应用不会自动读取 `.env`）：

| 变量             | 默认值              | 用途                                          |
| ---------------- | ------------------- | --------------------------------------------- |
| `HOST`           | `127.0.0.1`         | 监听地址，局域网测试用 `0.0.0.0`              |
| `PORT`           | `4310`              | HTTP 端口                                     |
| `DATA_DIR`       | 应用目录下 `.data/` | 持久化数据目录                                |
| `PUBLIC_URL`     | 自动检测局域网地址  | 二维码链接的完整网址（部署时填写 HTTPS 网址） |
| `SECURE_COOKIES` | 未开启              | 正式 HTTPS 部署时设为 `1`                     |

正式部署计划是轻量 Node 服务 + SQLite + HTTPS 反向代理，不需要托管数据库或对象存储。现有 VPN 占用 TCP/UDP 443；需要单独规划 HTTPS 的端口、防火墙与证书续期，完成验证后再切换，不直接覆盖 VPN。
